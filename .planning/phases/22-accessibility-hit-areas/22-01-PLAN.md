## Objective

Refactor the application shell and sidebar navigation to native HTML `<button type="button">` elements with `aria-current="page"`, visible `:focus-visible` rings, and keyboard-activated tooltips (`UI-16`). Transform the Ops Assistant chat panel from a blocking modal overlay into a docked, non-modal inspector that smoothly insets the `.content-area`, maintains resizability (340px–900px), removes the blocking modal backdrop, and supports `Escape` close with focus restoration and a global `Ctrl+/` toggle hotkey (`UI-08`).

## Threat Model

<threat_model>
- **TM-01 (Denial of Service / Unresponsive Keyboard Trap):** If the chat panel retains a transparent full-screen overlay or intercepts keydown events without releasing focus, users navigating via keyboard could get trapped. *Mitigation:* Remove `.chat-overlay` in docked mode; explicitly handle `Escape` to close and return focus to the invoking trigger; do not trap focus globally in non-modal mode.
- **TM-02 (Accidental Form Submission):** Using `<button>` elements without `type="button"` inside a page could trigger unexpected form submissions if wrapped in a parent form. *Mitigation:* All converted sidebar navigation and action buttons must explicitly declare `type="button"`.
</threat_model>

     ```jsx
       type="button"
       ref={chatToggleRef}
       className={`sidebar-nav-item chat-nav-item ${chatOpen ? 'active' : ''}`}
       onClick={() => setChatOpen(!chatOpen)}
       aria-expanded={chatOpen}
       aria-controls="ops-assistant-panel"
       aria-label="Ops Assistant"

     </button>
     ```

   - Add a global `keydown` event listener in `App.jsx` for `Ctrl+/` (or `Cmd+/`) to toggle `chatOpen`:
     ```jsx

       const handleGlobalKeyDown = (e) => {
         if ((e.ctrlKey || e.metaKey) && e.key === '/') {

           setChatOpen(prev => !prev);
         }
       };
       window.addEventListener('keydown', handleGlobalKeyDown);
       return () => window.removeEventListener('keydown', handleGlobalKeyDown);
     }, []);
     ```
   - In the `.app-shell` JSX, add the dynamic class `chat-open` when `chatOpen` is true:
     `className={`app-shell ${chatOpen ? 'chat-open' : ''}`}`.
</action>

<action>
1. In `dashboard/src/ChatPanel.jsx`:
   - Accept optional `triggerRef` or `onClose` callback in props.
   - When closing via `onClose` (from close button or Escape), call `onClose()` and restore focus to `triggerRef.current?.focus()`.
   - Add an `Escape` key event listener on `.chat-panel` or `window` while open to trigger close and restore focus:
     ```jsx
     useEffect(() => {
       if (!isOpen) return;
       const handleKeyDown = (e) => {
         if (e.key === 'Escape') {
           e.stopPropagation();
           onClose();
           if (triggerRef?.current) {
             triggerRef.current.focus();
           }
         }
       };
       window.addEventListener('keydown', handleKeyDown);
       return () => window.removeEventListener('keydown', handleKeyDown);
     }, [isOpen, onClose, triggerRef]);
     ```
   - Remove `<div className="chat-overlay" onClick={onClose} />` from the render tree when in docked mode, eliminating the modal blocker.
   - On the root panel div:
     ```jsx
     <div
       id="ops-assistant-panel"
       role="region"
       aria-label="DNAC Ops Assistant"
       className="chat-panel docked"
       style={{ width: panelWidth }}
     >
     ```
   - Wire the panel width to a CSS variable `--chat-panel-width: ${panelWidth}px` on document root or the shell so `.content-area` insets seamlessly during resize.
