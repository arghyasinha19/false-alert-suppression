## Objective

Enhance `workflow/tools/dnac_status.py` so that alert status verification cross-references live device reachability (`client.get_device_health(device_id)` and raw response state) when Assurance issues return no exact match. When a device is explicitly confirmed unreachable in Cisco DNA Center (`communicationState: UNREACHABLE` / `reachabilityStatus: Unreachable`), acknowledge the alert as `ACTIVE` rather than falling through to `UNCERTAIN`. Support auto-resolution of `device_id` via `device_name`/IP, update `workflow/delayed.py` to forward normalized device parameters, maintain full backwards compatibility for existing unit tests, and add comprehensive automated tests in `tests/test_live_reachability_verification.py`.

## Must-Haves (Goal-Backward Verification)

<must_haves>
### Truths
- When an alert's `issue_id` is missing or not found, and `client.get_device_issues()` yields no active/resolved matches on the device, `check_alert_status` queries live reachability via `client.get_device_health(device_id)` (`DNAC-03`).
- If DNAC confirms the device is explicitly unreachable (`health.reachable is False`, `reachabilityStatus == "Unreachable"`, or `communicationState == "UNREACHABLE"`), `check_alert_status` returns `ACTIVE` instead of `UNCERTAIN` (`DNAC-03`).
- If the alert is a reachability-type alert (e.g., contains keywords like "unreachable", "connectivity", "connection timeout", "ping", "down"), the device is confirmed reachable (`health.reachable is True`), and zero active issues exist on the device, `check_alert_status` returns `RESOLVED` (`DNAC-03`).
- If the alert is an unmatched non-reachability alert (e.g., "BGP peer down") and the device is reachable, `check_alert_status` returns `UNCERTAIN` to escalate to ServiceNow (`DNAC-03`).
- If `device_id` is omitted in the alert but `device_name` is present, `check_alert_status` attempts to resolve `device_id` using `client.get_device_by_name_or_ip(device_name)` before giving up (`DNAC-03`).
- In `workflow/delayed.py`, `run_delayed_check()` forwards `device_name=alert.get("device_name") or alert.get("device")` and `device_id=alert.get("device_id")`.
- Existing tests in `test_dnac_fallback.py` pass without regression.
- New test suite in `tests/test_live_reachability_verification.py` verifies all reachability cross-referencing cases with 100% pass rate.

## Step-by-Step Implementation

### Step 1: Update `workflow/tools/dnac_status.py`
1. Define reachability keyword recognizer:
   ```python
   _REACHABILITY_KEYWORDS = (
       "unreachable",
       "reachability",
       "connectivity",
       "connection timeout",
       "ping",
       "offline",
       "disconnect",
       "dev-unreached",
       "ncim12013",
   )

   def _is_reachability_alert(issue_name: Optional[str]) -> bool:
       target = _norm(issue_name)
       return any(kw in target for kw in _REACHABILITY_KEYWORDS)
   ```
2. In `check_alert_status()`:
   - If `not device_id` and `device_name`:
     ```python
     if not device_id and device_name and hasattr(client, "get_device_by_name_or_ip"):
         try:
             found_devs = client.get_device_by_name_or_ip(device_name)
             if found_devs and isinstance(found_devs, list):
                 device_id = found_devs[0].get("device_id")
         except Exception as exc:
             logger.debug(f"Device name resolution failed for {device_name}: {exc}")
     ```
   - After testing `client.get_device_issues()` for ACTIVE and RESOLVED/IGNORED matches:
     If no match was found:
     Check device reachability via `client.get_device_health(device_id)`:
     ```python
     if hasattr(client, "get_device_health"):
         try:
             health = client.get_device_health(device_id)
             if isinstance(health, dict):
                 is_reachable = health.get("reachable")
                 raw = health.get("raw_response", {}) if isinstance(health.get("raw_response"), dict) else {}
                 raw_net = raw.get("network_device", {}) if isinstance(raw.get("network_device"), dict) else {}
                 raw_detail = raw.get("device_detail", {}) if isinstance(raw.get("device_detail"), dict) else {}

                 reach_status = str(raw_net.get("reachabilityStatus", "")).lower()
                 comm_state = str(raw_detail.get("communicationState", "")).upper()
                 is_unreachable = (
                     is_reachable is False
                     or reach_status in ("unreachable", "false")
                     or comm_state in ("UNREACHABLE", "DISCONNECTED")
                 )

                 if is_unreachable:
                     fail_reason = raw_net.get("reachabilityFailureReason") or comm_state or "Unreachable"
                     logger.info(
                         f"Device scan fallback: device {device_id} is explicitly UNREACHABLE "
                         f"in DNAC ({fail_reason}). Acknowledging alert as ACTIVE."
                     )
                     return ACTIVE

                 if is_reachable is True and _is_reachability_alert(issue_name):
                     logger.info(
                         f"Device scan fallback: device {device_id} is REACHABLE with no active "
                         f"issues in DNAC for reachability alert '{issue_name}'. Returning RESOLVED."
                     )
                     return RESOLVED
         except Exception as exc:
             logger.warning(f"DNAC live reachability check failed for device {device_id}: {exc}")
     ```
   - Fall back to `UNCERTAIN` if reachability does not definitively resolve the alert.

### Step 2: Update `workflow/delayed.py`
1. In `run_delayed_check(alert)`:
   Ensure `device_name` falls back to `alert.get("device")` if `alert.get("device_name")` is absent.
   Ensure `issue_id` falls back to `alert.get("instance_id")` if `alert.get("issue_id")` is absent.

### Step 3: Create Dedicated Test Suite `tests/test_live_reachability_verification.py`
1. Test unreachable device returns `ACTIVE` when Assurance issue is missing or empty.
2. Test device with SNMP Connectivity failure (`NCIM12013` / `DEV-UNREACHED`) returns `ACTIVE`.
3. Test reachable device with restored connectivity returns `RESOLVED` for reachability alerts.
4. Test reachable device with unmatched non-reachability alert (e.g., "BGP peer down") returns `UNCERTAIN`.
5. Test device resolution by hostname/IP when `device_id` is not pre-populated.
6. Test end-to-end `run_delayed_check()` flow escalates unreachable devices with "Non-Auto Resolving".

### Step 4: Run Verification Suite

2. Run `pytest tests/test_live_reachability_verification.py`.
3. Run `pytest tests/test_device_telemetry_api.py tests/test_frontend_sre_drawer_contract.py`.
